# B-08 · Step 3 What-if chat (multi-turn) with before → after diff
**Track:** B · **Level:** L2 · **Estimate:** 75 min · **Branch:** `track-b`
**Depends on:** B-05

> Read `CLAUDE.md`. E.g. "leave three players home", "cap lodging at $9,000". The model returns a structured patch; code
> validates and applies it, recomputes every package and reports what changed.

## Context
- `api.whatIf({ params: { id }, body: { message } })` → `WhatIfResponse = { reply, needs_clarification, clarifying_question,
  patch_ops: PatchOp[], rejected_ops: [{op, reason}], applied, diff: [{option_id, before_total, after_total, delta, changes[]}],
  trip, source: 'ai'|'fallback' }`. The server keeps history in `trip.whatif_history: [{role, content}]`.
- `PatchOp` variants: set_count{field,value}, adjust_count{field,delta}, set_cap{category,max}, clear_cap{category},
  set_departure_constraint{constraint}, exclude_hotel{hotel_id}, set_equipment_truck{value}, prefer{criterion}.
- Mock mode understands: "leave N players home", "cap lodging at $X", "no equipment truck".

## Steps
1. `WhatIfStep.tsx`: chat list rendered from `trip.whatif_history`; input + Send (disabled while pending; show a typing indicator).
2. Suggested prompt chips: "Leave three players home", "Cap lodging at $9,000", "No equipment truck", "Can't leave before 2 PM Friday".
3. Per response, below the assistant bubble:
   - applied op chips in human words by code (e.g. "Players −3", "Lodging cap $9,000", "Truck off").
   - rejected ops in amber with the reason. A clarifying question shows as an assistant bubble.
   - **Diff table**: per option label → before → after total (`Money`) and the delta (`MoneyDelta`), then the change strings.
4. Write `response.trip` into the `['trip', id]` cache so the Packages step shows new numbers. A "View packages" button → goTo.
5. `source === 'fallback'` → `AiNotice` in the thread ("AI is unavailable — edit the request form instead") + a link to the Request step.
