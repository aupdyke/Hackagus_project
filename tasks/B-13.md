# B-13 · Season budget screen
**Track:** B · **Level:** EXT · **Estimate:** 75 min · **Branch:** `track-b`
**Depends on:** B-01 (A-15 for real numbers; fixtures until then)

> Read `CLAUDE.md`. Demo step 1 opens here: "Season over budget". It must read clearly on a projector.

## Context
- `api.getSeason()` → `SeasonRollup = { budget, committed, projected, remaining, over_budget, rows: SeasonRow[],
  actuals: { trips_completed, planned_total, actual_total, variance } }`.
- `SeasonRow = { trip_id, game_id, opponent, date, status, selected_option_id, selected_label, planned_cost|null, actual_cost|null,
  variance|null, risk_count, counts_toward: committed|projected|none }`.
- Definitions (code): committed = approved + published + completed (actuals when entered); projected = committed + drafts;
  remaining = budget − projected.

## Steps
1. Replace `app/(staff)/season.tsx`:
   - **Budget gauge**: a horizontal bar with the budget as 100%: committed segment (brown), draft segment (orange), and a marker line
     at the budget. Over budget → red overflow + an "Over budget by $X" banner (X = −remaining, computed by the server's numbers).
   - KPI tiles: Budget, Committed, Projected, Remaining (each `Money` + Estimate).
   - "Get back under budget" primary button (visible when over_budget) → `router.push('/(staff)/savings')` (B-14 builds the screen).
   - Per-trip list/table: date, at Opponent, `StatusChip`, package label, planned, actual, variance (colored), risk count chip; tap →
     `/(staff)/trips/[id]`.
   - Actuals roll-up card: completed trips with actuals, planned vs actual, variance.
   - Pull-to-refresh; "Switch role" ghost button stays at the bottom.
2. Use `View` widths for the bar (no chart library).

## Files
