# B-02 · Trips list + 7-step trip workflow stepper
**Track:** B · **Level:** L1 · **Estimate:** 60 min · **Branch:** `track-b`
**Depends on:** B-01

> Read `CLAUDE.md`. The stepper makes the workflow easy for a first-time user (Usability is 10 pts).

## Context
- Screens: `app/(staff)/trips/index.tsx` (list shell), `app/(staff)/trips/[id].tsx` (detail shell), inside the Trips tab stack.
- `TripSummary` (list): trip_id, opponent, city, state, date, kickoff_local, status, selected_label, estimated_total, risk_count.
- `TripDetail` (`api.getTrip`): `{ trip, game }`.
- Steps (spec §8): 1 Request → 2 Packages → 3 What-if → 4 Memo → 5 Rooming → 6 Approve & Publish → 7 Actuals.

## Steps
1. Trips list: a card per away trip (opponent, formatted date, city, `StatusChip`, estimate via `Money` when present, a risk count
   chip). Pull-to-refresh. Upcoming trips first, then completed (dimmed).
2. `components/staff/Stepper.tsx`: horizontal, scrollable step pills with numbers. Current step highlighted orange, completed
   steps get a check, disabled steps greyed. Large tap targets.
   Enabled rules: Packages needs `trip.request`; What-if and Memo need packages; Rooming and Publish need `selected_option_id`;
   Actuals needs status published or completed.
3. `[id].tsx`: header "at <opponent>", game line (date, kickoff, stadium), Stepper, then the active step component.
   Initial step from status: not_started → Request, draft → Packages, approved → Publish, published → Publish, completed → Actuals.
4. Create placeholder step components (one file each, so later tasks don't conflict):
   `components/staff/steps/{RequestStep,PackagesStep,WhatIfStep,MemoStep,RoomingStep,PublishStep,ActualsStep}.tsx`,
   each `({ detail, goTo }: StepProps)`, where `goTo(step)` changes the step. Export the `StepProps` type from `steps/types.ts`.

## Files
- modify `app/(staff)/trips/index.tsx`, `app/(staff)/trips/[id].tsx`
- create `components/staff/Stepper.tsx`, `components/staff/steps/*.tsx`, `components/staff/steps/types.ts`
