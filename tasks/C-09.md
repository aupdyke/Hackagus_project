# C-09 · Roommate requests (up to 2, deadline + locked states)
**Track:** C · **Level:** EXT · **Estimate:** 60 min · **Branch:** `track-c`
**Depends on:** C-01 (A-10 sets `roommate_deadline_local` on trips)

> Read `CLAUDE.md`. Before a staff-set deadline, athletes can request up to 2 roommates from that trip's travel roster. The
> rooming algorithm honors mutual requests first. Athletes see their final roommate after publish.

## Context
- `api.myTrip(...)` → `open_roommate_requests: [{ trip_id, opponent, deadline_local }]` (draft/approved trips this athlete travels on,
  with a deadline set) and `trip` (published view with `roommates`).
- `api.travelRoster({ params:{ id: athleteId, tripId } })` → `[{ id, name, position_group, class_year }]` (excludes self;
  409 if the athlete isn't on that roster).
- `api.getRoommateRequest({ params:{ id, tripId } })` → `RoommateRequest | null`.
- `api.roommateRequest({ params:{ id }, body:{ trip_id, requested_ids } })` → saved request. Errors: 409 deadline passed / rooming final,
  400 not on roster / self.

## Steps
1. Replace `app/(athlete)/roommates.tsx`:
   - If there's an open trip: header "at <opponent> · pick by <deadline (formatDayTime)>" + a countdown; the current saved picks as
     chips (removable); a searchable roster list grouped by position group with a select toggle; selecting a third shows "You can
     pick up to 2". Save button → POST → "Saved ✓" state. Explain: "Mutual requests are matched first. Staff make the final call."
   - If the deadline passed (409 or local check) → a locked state showing the saved picks read-only.
   - If a published trip exists → "Final rooming: Room RM-04 with <names>".
   - Otherwise → Empty "No trips open for roommate requests".
2. Multiple open trips → a segmented picker at the top.
