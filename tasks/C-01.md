# C-01 · Role switch + athlete picker
**Track:** C (Athlete + ship) · **Level:** L1 · **Estimate:** 45 min · **Branch:** `track-c`
**Depends on:** none (Phase 0)

> Read `CLAUDE.md`. There's no real authentication (documented in the README): a demo role switch at launch, Staff or Athlete
> with a picker of synthetic players. The app sends `X-Role` / `X-Athlete-Id`, and the server scopes athlete data by id.

## Context
- `app/index.tsx` (Phase 0 version) lists the first 40 athletes. `lib/role.tsx` (`useSession().setSession({role, athleteId, athleteName})`)
  is contract-shared: don't change its API.
- `api.listAthletes()` → `[{ id, first_name, last_name, jersey, position, position_group, class_year }]` (100 players).
- `api.health()` → `{ ai_mode: mock|live|disabled }`.

## Steps
1. Landing screen: BGSU-branded hero (brown header, orange accent), app name, the one-line purpose, a server status pill
   ("Server OK · AI live/mock/off", or an error with Retry showing the URL it tried), two big buttons **Staff** / **Student-athlete**.
   A small "Synthetic data · demo role switch (no login)" footer and "Dev: streaming test" as a tiny link.
2. Athlete picker: search (name or jersey), position-group filter chips (All, QB, RB, WR, TE, OL, DL, LB, DB, ST), a `FlatList`
   of all 100 players (jersey bubble, name, position, class year). Tap → set the session → `router.replace('/(athlete)/my-trip')`.
3. Athlete tab header: a right-side "Switch" button that returns to `/` (edit `app/(athlete)/_layout.tsx` `screenOptions.headerRight`).
4. Keep the staff path the same (`/(staff)/season`).

## Files
- modify `app/index.tsx`, `app/(athlete)/_layout.tsx`; create `components/athlete/AthletePicker.tsx`

## Acceptance criteria
- [ ] Any of the 100 players can be picked in ≤ 3 taps; switching roles works from both sides.

## How to verify
`npm run dev:mock` → launch → Student-athlete → search "21" or "Kettering" → pick → My Trip → Switch → back to landing.
