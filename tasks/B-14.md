# B-14 · "Get back under budget" screen (AI-selected savings, code-computed totals)
**Track:** B · **Level:** EXT · **Estimate:** 60 min · **Branch:** `track-b`
**Depends on:** B-13 (A-16 for real data)

> Read `CLAUDE.md`. Code lists candidate swaps and their savings; Aivana picks a set by ID and explains why. The model never
> states a dollar figure, so everything numeric comes from code fields. Demo step 10.

## Context
- `api.seasonSavings({ body: {} })` → `SavingsResult = { candidates:[{candidate_id, kind, trip_id, description, savings,
  new_option_id}], selected_candidate_ids[], explanation, projected_before, projected_after, total_savings, back_under_budget,
  source: 'ai'|'template', fact_guard }`.
- `api.applySavings({ body: { candidate_ids } })` → new `SeasonRollup`.

## Steps
1. Create `app/(staff)/savings.tsx` and register it hidden in `app/(staff)/_layout.tsx`:
   `<Tabs.Screen name="savings" options={{ href: null, title: 'Get back under budget' }} />`.
2. On open → `useSavings` (loading: "Finding savings…").
3. UI: header "Projected $X → $Y" (`projected_before` → `projected_after`) + "Back under budget" / "Still over" chip; AI explanation
   card with source chips (template / replaced, like B-06); candidate list with checkboxes (AI-selected pre-checked with an "AI pick"
   chip), description, kind icon, savings `Money`.
4. When staff change the selection, show "Totals will be recomputed when you apply" (don't compute projected client-side).
5. "Apply selected" → confirm → `useApplySavings` → invalidate season/trips → back to Season showing the new numbers.
6. Errors → `AiNotice`; the candidates list still works (template result).
