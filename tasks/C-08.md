# C-08 · Notification polling, tab badge, local notifications
**Track:** C · **Level:** EXT · **Estimate:** 60 min · **Branch:** `track-c`
**Depends on:** C-07

> Read `CLAUDE.md`. The inbox has a badge and polls every 30–60 s and when the app comes to the foreground. Optionally fire
> a **local** notification. **No remote APNs push** (too risky for the timeline).

## Context
- React Query `focusManager` is wired to `AppState` in `app/_layout.tsx`, so `refetchOnWindowFocus` fires on foreground.
- `expo-notifications` is installed and in app.json plugins. Local only: `Notifications.scheduleNotificationAsync({ content:{title, body},
  trigger: null })`, `Notifications.setNotificationHandler(...)`, `Notifications.requestPermissionsAsync()`.
- Inbox query key `['notifications', athleteId]`.

## Steps
1. `apps/mobile/lib/notifications.ts`:
   - `useNotificationsQuery(athleteId)`: `refetchInterval: 45_000`, `refetchOnWindowFocus: true`, `refetchIntervalInBackground: false`.
   - `useUnreadCount(athleteId)`.
   - `useLocalNotify(athleteId)`: keeps a ref of seen notification ids (initialized from the first fetch so old items don't
     fire); for each newly arrived unread item → schedule a local notification (title/body from the item). Ask permission once,
     on first athlete login, and handle denial gracefully (badge still works).
   - Call `Notifications.setNotificationHandler` once (show the banner while the app is foregrounded).
2. `app/(athlete)/_layout.tsx`: Inbox tab `tabBarBadge={unread || undefined}`; mount `useLocalNotify` in the layout.
3. Make C-07's inbox use the same hook so there's one query.

## Files
- create `apps/mobile/lib/notifications.ts`; modify `app/(athlete)/_layout.tsx`, `app/(athlete)/inbox.tsx`
