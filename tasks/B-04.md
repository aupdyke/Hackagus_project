# B-04 · Step 1 Request: free text → AI parse → human review → confirm
**Track:** B · **Level:** L1 · **Estimate:** 75 min · **Branch:** `track-b`
**Depends on:** B-03

> Read `CLAUDE.md`. Hackathon rule: the parsed request is **shown to staff for confirmation and editing before costs are
> computed**. Never auto-submit a parse.

## Context
- `api.parseRequest({ body: { text } })` → `ParseResult = { draft: { game_id|null, opponent_text, players|null, coaches|null,
  support_staff|null, departure_constraint, include_equipment_truck|null, notes }, missing_fields[], ambiguities[{field,message}],
  source: 'ai'|'fallback', notice }`. When AI is down, the server returns 200 with `source: 'fallback'` and a friendly `notice`.
- Code (not AI) matched the opponent to the schedule and resolved the departure day/time.
- `RequestForm` from B-03 accepts `initial` + `missing`.

## Steps
1. Free-text mode in `RequestStep.tsx`: a multiline input (placeholder: "Ohio trip: 68 players, 12 coaches, 11 support staff,
   bring the equipment truck, can't leave before 2 PM Friday") + a "Parse with AI" button (loading state).
2. Review panel:
   - Banner "Review before computing costs" + a "Parsed by AI" chip (or `AiNotice` with `notice` when source = fallback).
   - Ambiguities as a list of warnings, each next to its field.
   - If `draft.game_id` ≠ this trip's game: warn "Your text mentions <opponent_text> — this screen plans at <opponent>." and keep
     this trip's game.
   - `RequestForm` prefilled with the draft; `missing` fields highlighted; the "Confirm & compute packages" button stays disabled
     until every required field has a value.
   - "Start over" clears the review.
3. Confirm → `useSubmitRequest` (same as the form) → Packages step.
4. Error states: `isAiError` → `AiNotice` with the friendly message plus a "Use the form instead" button.
