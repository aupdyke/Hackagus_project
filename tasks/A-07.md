# A-07 · What-if chat: structured patch → validate → apply → recompute → diff
**Track:** A · **Level:** L2 · **Estimate:** 90 min · **Branch:** `track-a`
**Depends on:** A-03, A-04

> Read `CLAUDE.md`. Multi-turn + structured output. The model proposes a **patch**; code validates, applies and recomputes.
> The model never states dollar figures.

## Context
- Stubs in `packages/shared/src/logic/whatif.ts`: `aiOpsToPatch`, `applyPatch`, `diffPackages`.
- Typed `PatchOp` (domain.ts): `set_count{field,value}`, `adjust_count{field,delta}`, `set_cap{category,max}`, `clear_cap{category}`,
  `set_departure_constraint{constraint}`, `exclude_hotel{hotel_id}`, `set_equipment_truck{value}`, `prefer{criterion}`.
- The AI schema is flattened (no `oneOf` allowed). `WHATIF_SCHEMA` + `AiWhatIfOut` in `ai/schemas.ts`:
  `{ reply, needs_clarification, clarifying_question, patch_ops: [{ op, field, value, delta, category, max, hotel_id, criterion,
  constraint_kind, constraint_day, constraint_time_24h, bool_value }] }`. Unused fields hold sentinels ('' / -1 / 0 / 'none').
- Route stub: `whatIf` in `apps/server/src/routes/tripsAi.ts` (returns trip unchanged). Contract `WhatIfResponse` in `api.ts`:
  `{ reply, needs_clarification, clarifying_question, patch_ops, rejected_ops[{op,reason}], applied, diff: PackageDiff[], trip, source }`.
- `chat(messages, { schema, zod, feature:'whatif', system, max_tokens })` in `aivana/client.ts`. Trip has `whatif_history: ChatTurn[]`.
- Mock mode understands "leave N players home", "cap lodging at $X", "no equipment truck".

## Steps
1. `aiOpsToPatch(ops, { game, data })`: convert each flattened op and reject invalid ones with a reason:
   set_count needs a field and value ≥ 0; adjust_count needs a field and delta ≠ 0; set_cap needs a category and max > 0;
   set_departure_constraint resolves `constraint_day` with `resolveDay(game.date, day)` plus `isValidClock(time)` into
   `{kind, datetime_local, raw_text}`; exclude_hotel needs a hotel in `game.city`; set_equipment_truck needs yes/no;
   prefer needs a criterion ≠ none.
2. `applyPatch(req, ops, ctx)`: apply ops in order to a copy. Reject (don't clamp) any op that would break the TripRequest bounds
   or exceed the eligible player count. Return `{ request, rejected }`.
3. `diffPackages(before, after)`: match by option_id; `delta = after.total − before.total`. `changes` strings come from code, e.g.
   `"Players 70 → 67"`, `"Rooms 56 → 54"`, `"Buses 2 → 2"`, `"Hotel X → Y"`, `"Total $30,762 → $29,980"` (formatUSD),
   `"Now infeasible: …"`.
4. Route (replace the stub). Allowed for draft / approved (→ back to draft) / published (stays published; needs re-publish);
   completed → 409.
   - System prompt (< 150 words): you translate staff requests into patch ops for the current trip; only use hotel ids from
     FACTS; ask a clarifying question if unclear; reply in ≤ 2 sentences with no dollar figures; `FACTS_RULE`.
     FACTS = `{ request: {players,coaches,support_staff,constraint,truck,caps,excluded}, game_date, options:[{id,label,hotel_id}],
     hotels:[{hotel_id,name}] }` (compact).
   - messages = last **8** turns of `whatif_history` + the new user message. `max_tokens: 500`, `temperature: 0`.
   - needs_clarification → return the question, applied false, trip unchanged (append the turns).
   - Else convert → apply → `computeTripPackages` → diff → clear `recommendation` (stale) → append the turns → save.
   - `factGuard(reply, factsFromPackages(after) ∪ request numbers)`. On failure, replace the reply with a code summary of the applied ops.
   - `AiError` → 200 with `source: 'fallback'`, the friendly message as reply, applied false.
5. Tests: unit tests for all three functions; route test (mock) "leave three players home" → players −3, every option has a
   diff, the response trip has the new request; an invalid hotel id is rejected with a reason.
