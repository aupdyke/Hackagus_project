# A-13 · Publish → versions → athlete view → per-athlete change notifications
**Track:** A · **Level:** EXT · **Estimate:** 90 min · **Branch:** `track-a`
**Depends on:** A-10 (rooming/buses), A-03

> Read `CLAUDE.md`. Each publish creates a new trip **version**. Code diffs each athlete's view against the previous
> version and writes notifications listing **only what changed for them**, in plain words generated by code (no AI).

## Context
- Stubs in `packages/shared/src/logic/athlete.ts`: `buildAthleteView`, `diffAthleteViews`, `describeChanges`.
- Route stubs: `publishTrip` (`routes/tripsPublish.ts`, saves a version snapshot but no notifications),
  `myTrip` + `notifications` (`routes/athletes.ts`, return fixtures while `diffAthleteViews` is a stub; `isStubDiff()`).
- Repo: `repo.versions.get(tripId, v)` / `.save(trip)`, `repo.notifications.save(n)` / `.listFor(athleteId)`.
- `AthleteTripView` (domain.ts): trip_id, version, athlete_id, game, hotel{hotel_id,name,address,phone}, bus_number, room_id,
  roommates[{id,name}], itinerary, meals[{meal_id,kind,time_local,vendor_name,itinerary_item_id}], packing_list,
  departure_local, roommate_deadline_local, published_at, share_url.
- `ChangeItem = { kind: time|hotel|bus|roommate|meal|added|removed, item_id, label, before, after }`.
- `AthleteNotification = { id, athlete_id, trip_id, version, created_at, title, body, changes, read }`.

## Steps
1. `buildAthleteView(trip, game, hotel, athlete, data, settings, shareUrl)` from the selected package plus `trip.buses` and
   `trip.rooming`. Roommate names via the roster (`first last`).
2. `diffAthleteViews(before | null, after)`: before null → `[]`. Match itinerary items by `kind + label` (ids may shift):
   start time changed → `time` (before/after via `formatDayTime`); missing → `removed`; new → `added`. Also hotel name → `hotel`,
   bus_number → `bus`, roommate set → `roommate`, meal vendor/time → `meal`.
3. `describeChanges(changes, opponent)`: no changes → title `"Your <opponent> trip is published"` with a body summarizing
   departure, bus and room. Otherwise title `"<opponent> trip updated: <first change summary>"` and body sentences like
   `"Buses now depart Fri Nov 27 at 12:00 PM (was 11:00 AM)."`, `"Your roommate is now Jory Kettering (was Nico Redfern)."`
4. `publishTrip` (replace the TODO):
   - requires approved or published plus a selected package; if rooming is missing, generate it (A-10 helper) and save
     traveling ids + buses.
   - version++, `share_token` if empty, `published_at`; `repo.versions.save(newTrip)`.
   - For each traveling player: newView vs the previous version's view (if the athlete was on it) → diff. First publish (or newly
     added athlete) → a "published" notification; changes → an "updated" notification; no changes → nothing. Athletes dropped
     from the roster → a notification with a `removed` change "You are no longer on the travel roster for <opponent>".
   - id `N-<tripId>-v<version>-<athleteId>`.
5. `myTrip`: pick the earliest upcoming published trip (game date ≥ today, else the most recent published) whose
   `traveling_player_ids` include the athlete → `buildAthleteView`; else `trip: null`. Keep `open_roommate_requests`.
6. `notifications`: remove the fixture fallback (`isStubDiff`).
7. Tests: diff unit tests (time change, roommate change, added/removed, no change). Route test: approve + publish v1 → athlete
   has a "published" notification → change the departure constraint (submit request) → select/approve as needed → publish v2 →
   notification lists the departure time change only.
