# C-07 · Inbox: change notifications (before → after)
**Track:** C · **Level:** EXT · **Estimate:** 45 min · **Branch:** `track-c`
**Depends on:** C-01 (A-13 for real notifications; fixtures until then)

> Read `CLAUDE.md`. Every time staff publish, code diffs each athlete's itinerary and creates notifications listing only
> what changed for them, in plain words (code-generated, no AI). Demo step 7.

## Context
- `api.notifications({ params:{ id } })` → `AthleteNotification[] = { id, trip_id, version, created_at, title, body,
  changes:[{kind: time|hotel|bus|roommate|meal|added|removed, item_id, label, before, after}], read }` (newest first).
- `api.markNotificationsRead({ params:{ id }, body:{ ids } })`.
- Query key `['notifications', athleteId]` (C-08 adds polling + the badge using the same key).

## Steps
1. Replace `app/(athlete)/inbox.tsx`: a list of cards; unread cards get an orange left border + dot. Title, relative time
   ("5 min ago"), body.
2. Expanded card shows the change rows: icon by kind, label, **before** (struck-through, muted) → **after** (bold). For `added` /
   `removed` show a single value. Tap an item with an `IT-*` id → My Trip `?focus=`.
3. Mark visible unread items as read when the screen is focused (debounced) → invalidate the key.
4. Empty: "No updates yet — you'll see changes here when staff update your trip." Pull-to-refresh.

## Files
