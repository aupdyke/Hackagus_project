# A-05 · AI package recommendation (structured, ID-checked, fact-guarded)
**Track:** A · **Level:** L1 · **Estimate:** 75 min · **Branch:** `track-a`
**Depends on:** A-04 (fact guard). Works on fixture packages until A-03 lands.

> Read `CLAUDE.md`. Aivana recommends one package **by option ID** and explains the tradeoffs. The app shows costs from
> our data only. Use of Aivana is worth 20 pts: sound schema, no model math, small prompts.

## Context
- Route stub: `apps/server/src/routes/tripsAi.ts` → `recommend` (currently returns `templateRecommendation` or a fixture).
- Schema (already written, passes `assertAivanaSchema`): `recommendSchema(optionIds)` + Zod mirror `AiRecommendOut` in
  `packages/shared/src/ai/schemas.ts`:
  ```json
  { "type":"object","additionalProperties":false,
    "required":["recommended_option_id","ranking","tradeoffs","explanation"],
    "properties":{
      "recommended_option_id":{"type":"string","enum":["PKG-G10-A","PKG-G10-B","PKG-G10-C"]},
      "ranking":{"type":"array","items":{"type":"string","enum":[...]},"minItems":1,"maxItems":3},
      "tradeoffs":{"type":"array","maxItems":3,"items":{"type":"object","additionalProperties":false,
         "required":["option_id","pros","cons"],"properties":{"option_id":{"type":"string","enum":[...]},
         "pros":{"type":"array","maxItems":3,"items":{"type":"string","maxLength":120}},
         "cons":{"type":"array","maxItems":3,"items":{"type":"string","maxLength":120}}}}},
      "explanation":{"type":"string","maxLength":700}}}
  ```
- Client: `generateStructured(schema, zod, { feature: 'recommend', system, prompt, max_tokens, temperature })` in
  `apps/server/src/aivana/client.ts`. It throws `AiError` (codes in `aivana/errors.ts`).
- Stubs to implement in `packages/shared/src/logic/facts.ts`: `recommendFacts`, `templateRecommendation`.
- `Recommendation` schema: `{ recommended_option_id, ranking, tradeoffs, explanation, source: 'ai'|'template', fact_guard, created_at }`.

## Steps
1. `recommendFacts(game, req, pkgs, hotels)` (you may add the `hotels: Hotel[]` param, a signature change inside Track A).
   It returns `{ facts, allowed }`:
   - facts (compact JSON): `{ game:{opponent,date,kickoff}, request:{players,coaches,support,constraint:raw_text,preference,caps},
     options:[{id,label,feasible,infeasible_reason,hotel,miles_to_stadium,meeting_room,team_meals,depart,return,nights,
     total,bus,hotel_cost,meals,risks:[{code,severity}]}] }`
   - allowed: `factsFromPackages(pkgs)` (A-04) plus hotel miles and the game date/kickoff.
2. `templateRecommendation(pkgs, now)`: a code-only pick: feasible first, then fewest critical flags, then fewest warnings,
   then lowest total. Ranking uses the same order. Pros/cons come from code comparisons ("Lowest total estimate",
   "Closest to the stadium (0.8 mi)", "Hotel team meals", "Over meal allowance", "No meeting room"…). The explanation template
   names the option ids and uses only code numbers. `source: 'template'`, `fact_guard: {passed:true, replaced:false, issues:[]}`.
3. `apps/server/src/features/recommend.ts`:
   - System prompt (< 150 words): role = travel coordinator assistant; weigh cost vs game readiness (arrival time, distance,
     meals, risks); respect `preference`; infeasible options must not be recommended; end with `FACTS_RULE`.
   - `prompt = "FACTS: " + JSON.stringify(facts)`, `max_tokens: 600`, `temperature: 0.2`.
   - Validate in code: the recommended id is in the list AND feasible; ranking ids are valid and unique; tradeoff ids are valid.
     An invalid id counts as a failure.
   - Run `factGuard` on the explanation plus every pro and con. On failure, **retry once** and append to the prompt:
     `"CORRECTION: your previous answer used values not in FACTS (<issues>). Use only FACTS."`
   - If it still fails: keep the AI's recommended id if valid (else the template's), replace the explanation and tradeoffs with the
     template's, and set `fact_guard: { passed:false, replaced:true, issues }`.
   - `AiError` → return `templateRecommendation` (the app shows "AI unavailable — showing code recommendation").
4. Replace the stub route: save `trip.recommendation`, return it.
5. Tests: unit tests for `recommendFacts.allowed` and `templateRecommendation`. A pure `finalizeRecommendation(aiOut, pkgs, allowed)`
   test for invalid id → template and invented `$` → replaced. Route test in mock mode returns `source: 'ai'` with a valid id.
