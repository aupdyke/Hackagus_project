# C-02 · EAS + expo-updates + FIRST TestFlight build (do this early!)
**Track:** C · **Level:** L1 · **Estimate:** 60 min (+ Apple processing time) · **Branch:** `track-c`
**Depends on:** none. Needs an **Apple Developer account** and an Expo account.

> Read `CLAUDE.md` and `docs/DEPLOY.md`. The demo is on an iPhone via TestFlight at 5:30 PM Saturday. Apple processing can
> take a long time, so get build #1 through now. Later JS changes ship with `eas update`.

## Context
- `apps/mobile/app.json`: name "Falcon Travel", slug `falcon-travel`, bundle id `edu.bgsu.hackathon.falcontravel`, plugins
  expo-router + expo-notifications, `runtimeVersion: { policy: 'appVersion' }`, updates enabled.
- `apps/mobile/eas.json`: development / preview / production profiles, each with `EXPO_PUBLIC_API_URL` in `env` (not secret;
  placeholder `https://REPLACE-WITH-YOUR-SERVER.onrender.com`).
- Never put `AIVANA_API_KEY` in eas.json or any `EXPO_PUBLIC_*` variable.

## Steps
1. `cd apps/mobile && npx eas-cli@latest login` (or `npm i -g eas-cli`).
2. `eas init` → commit the `extra.eas.projectId` it writes. `eas update:configure` → commit `updates.url`.
3. Bundle id: if Apple says it's taken, change it to something unique (e.g. add initials) in app.json and note it in DECISIONS.md.
4. App icon / splash: add `assets/icon.png` (1024×1024, BGSU orange background, white "FT"/falcon glyph, made with any tool) and
   reference it in app.json (`icon`, `splash.backgroundColor: '#4F2C1D'`). No transparency in the icon.
5. Set `build.production.env.EXPO_PUBLIC_API_URL` to the Render URL from C-03 (or a temporary cloudflared URL). It's baked in at
   build/update time; change it later with `eas update`.
6. `eas build -p ios --profile production` (let EAS manage credentials) → `eas submit -p ios --latest`.
7. App Store Connect → TestFlight → add internal testers (the demo phone's Apple ID). Install on the phone and confirm it launches,
   reaches the server (status pill) and the streaming test streams.
8. Verify OTA: change a string, `eas update --branch production --message "test"`, then reopen the app twice → see the change.
9. Write the real values (project id, bundle id, update channel; no secrets) into `docs/DEPLOY.md`.
