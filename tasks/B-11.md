# B-11 · Step 6 Approve & Publish + packet PDF + share link
**Track:** B · **Level:** L3 / EXT · **Estimate:** 60 min · **Branch:** `track-b`
**Depends on:** B-02 (A-11 / A-13 for real packets / notifications)

> Read `CLAUDE.md`. Publishing makes the trip visible to traveling athletes and creates a new version (athletes get
> change notifications). The staff packet includes costs (labeled Estimate).

## Context
- `useApprove(id)` → `api.approveTrip`, `usePublish(id)` → `api.publishTrip` (status published, `published_version`++,
  `share_token`, `published_at`).
- `api.getPacket({ params:{id}, query:{ audience:'staff' } })` → `{ title, html, share_url }`.
  Athlete version: `query: { audience:'athlete', athleteId }`.
- `expo-print`: `Print.printToFileAsync({ html })` → `{ uri }`. `expo-sharing`: `Sharing.shareAsync(uri, { mimeType: 'application/pdf',
  UTI: 'com.adobe.pdf' })`. Link: React Native `Share.share({ message: share_url, url: share_url })`.

## Steps
1. `PublishStep.tsx` summary: selected package (label, hotel, total `Money`), risk counts by severity, rooming status (generated? honored
   X/Y), memo status.
2. Actions by status: draft → "Approve plan" (needs a selected package); approved → "Publish to athletes"; published → "Re-publish
   changes" (enabled when `trip.updated_at > trip.published_at`) + "Version v{n} published <time>".
3. Packet buttons: "Staff packet (PDF)" → print → share sheet; "Athlete packet preview" (pick a traveling athlete from
   `trip.traveling_player_ids` + names) → PDF; "Share read-only link" → `Share.share`.
4. Confirm dialogs before publish ("Athletes on the travel roster will be notified").
