# C-03 · Deploy the backend (Render) + tunnel fallback
**Track:** C · **Level:** L1 · **Estimate:** 45 min · **Branch:** `track-c`
**Depends on:** none

> Read `CLAUDE.md` and `docs/DEPLOY.md`. A TestFlight build needs a public HTTPS backend. The Aivana key lives only in the
> host's environment settings.

## Context
- Server: `apps/server` (Express 5, TypeScript run with `tsx`; `npm start -w @falcon/server`). Reads `PORT`, `AIVANA_API_KEY`,
  `AIVANA_MOCK`, `PUBLIC_BASE_URL`, `DB_PATH`. SQLite via better-sqlite3 (falls back to a JSON file automatically if the
  native module can't build). Seeds itself on first start.
- SSE endpoints set `X-Accel-Buffering: no` so proxies don't buffer streams.

## Steps
1. Add `render.yaml` at the repo root (Blueprint):
   ```yaml
   services:
     - type: web
       name: falcon-travel-api
       runtime: node
       plan: free
       buildCommand: npm ci --include-workspace-root -w @falcon/server -w @falcon/shared
       startCommand: npm start -w @falcon/server
       healthCheckPath: /health
       envVars:
         - key: NODE_VERSION
           value: "22"
         - key: AIVANA_MOCK
           value: "0"
         - key: AIVANA_API_KEY
           sync: false
         - key: PUBLIC_BASE_URL
           sync: false
         - key: DB_PATH
           value: var/falcon.db
   ```
2. Create the service on Render from the repo (Blueprint or manual), set `AIVANA_API_KEY` and `PUBLIC_BASE_URL` in the dashboard.
3. Verify: `curl https://<svc>.onrender.com/health` → `ai_mode: "live"`; `curl -N -X POST https://<svc>/trips/TRIP-G12/memo/stream
   -H 'Content-Type: application/json' -d '{}'` streams progressively (not in one burst). If it's buffered, try Railway or the tunnel.
4. Tunnel fallback: on a laptop, `npm run dev:server` + `cloudflared tunnel --url http://localhost:3000`; verify the same two curls
   against the tunnel URL. Write the exact commands that worked into DEPLOY.md.
5. Post the backend URL in team chat; update `eas.json` production/preview `EXPO_PUBLIC_API_URL` (not secret).
6. Note in DEPLOY.md: a redeploy resets the SQLite DB (it re-seeds), so don't redeploy right before the demo; warm the free tier
   1–2 min before.
