## Context

  `data/generate.ts`).
- `getSeason` route uses `orFixture` (goes live automatically). Packages for a request: `buildPackages`.

## Rules
- committed = Σ approved/published selected totals + Σ completed (actual total if entered, else selected total).
- projected = committed + Σ drafts (selected total, else cheapest feasible). not_started contribute 0.
- remaining = budget − projected; over_budget = projected > budget. Rows for every away trip, sorted by date.
- counts_toward: approved/published/completed → committed; draft → projected; not_started → none.
- Candidates only for **draft and approved** trips:
  - `switch_package`: one per cheaper feasible package than the current selection (or than the cheapest, for unselected drafts that's 0 → skip).
  - `reduce_travelers`: players − 5, rebuilt with `buildPackages`, same tier as the current selection; savings = current − new.
  - `cheaper_hotel`: rebuild with the current hotel added to `excluded_hotel_ids`, same tier; include only if cheaper and feasible.
  - Descriptions by code: `"Buffalo: switch Game-Ready → Economy"`, `"Buffalo: travel 5 fewer players"`,
    `"Buffalo: use <hotel> instead of <hotel>"`. Sort by savings desc and number SAV-1….
- `applySavings`: validate ids; per trip apply at most one `switch_package` (largest wins); savings are additive otherwise
  (approximation, documented). Return `{ projected_after, total_savings }`.
